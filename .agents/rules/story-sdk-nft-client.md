### TL;DR

The **NftClient** is used to create and manage specialized NFT collections (SPG Collections) that are natively compatible with Story Protocol. These collections serve as the "containers" for IP Assets, allowing for automated registration, fee management, and metadata handling within the Story ecosystem.

---

## Core NftClient Methods

### 1. createNFTCollection

This is the primary method for initializing your creative project's presence on Story. It deploys a new SPG (Story Protocol Gateway) NFT contract.

* **Public vs. Private**: `isPublicMinting` determines if anyone can mint from the collection or only authorized minters.
* **Fee Structure**: You can set a `mintFee` and specify the `mintFeeToken` (e.g., $WIP or $USDC) along with a `mintFeeRecipient`.
* **Supply & Metadata**: Supports setting a `maxSupply` and defining a `baseURI` or `contractURI` (ERC-7572 compliant) to manage how the world sees your collection.

### 2. URI Management

SPG collections offer flexible metadata handling to ensure your creative assets are properly represented.

* **setTokenURI**: Manually updates the metadata link (e.g., an IPFS CID) for a specific token ID.
* **getTokenURI**: Retrieves the current metadata link for a specific asset.
* **Base URI Logic**: If a `baseURI` is set during creation, individual token URIs can be automatically generated by appending the token ID.

### 3. Fee & Token Queries

Useful for frontend applications to display costs to users:

* **getMintFee**: Returns the `bigint` value required to mint an asset from the specified contract.
* **getMintFeeToken**: Identifies which ERC-20 token is accepted for minting fees in that collection.

## Technical Parameters Table

| Parameter | Type | Description |
| --- | --- | --- |
| **spgNftContract** | `Address` | The unique contract address of the SPG collection. |
| **mintOpen** | `boolean` | Whether the collection accepts new mints immediately. |
| **isPublicMinting** | `boolean` | Permission toggle for open minting. |
| **contractURI** | `string` | Link to collection-level metadata (logo, description). |

## Implementation Example: Creating a Collection

For your work on the **Creative Platform**, you would typically call this once to create a "master collection" for your artists or AI agents to mint into.

```typescript
const newCollection = await client.nftClient.createNFTCollection({
  name: "Creative Professionals Collection",
  symbol: "CPC",
  isPublicMinting: false, // Only your platform agents can mint
  mintOpen: true,
  mintFeeRecipient: "0xYourTreasury...", 
  contractURI: "https://ipfs.io/ipfs/...",
});

// Capture this address to use in IPAsset registration:
const collectionAddress = newCollection.spgNftContract;

```

### Application for Creative Platform

Since you are building an **IP marketplace**, the `NftClient` is your first step. Before an artist can register an **IP Asset**, they (or your AI agents) need an SPG-compatible NFT contract to house those assets. You can use the `spgNftContract` address returned here as the input for the `registerIpAsset` method in the **IPAssetClient**.
